# Parity with the Python SDK

This page states what `claude-agent-rust-sdk` was compared against, how much of the
Python Claude Agent SDK it covers, each reviewed difference with its reason and
the test or case that shows it, and the differences found but not yet reviewed. Read it before you port a program, to see
where a line-by-line translation behaves differently.

Most of the page is generated by `cargo xtask parity-page` from the parity
ledgers in [`parity/`](../parity), and `cargo xtask parity-check` fails when it
is out of date, so the counts below are measured, not stated. The sections
after the generated region are written by hand.

How to read it:

- **Not ported** means the Rust crate has no counterpart for an upstream item
  (an export or a test), for the reason its ledger gives.
- **Deliberately different** means both SDKs have the feature and behave
  differently on purpose. A difference on the wire (what each SDK sends the CLI)
  is found by the differential harness, which plays the same case through both
  SDKs against a scripted stand-in CLI; a difference in behavior (how a message
  is parsed, how the child process is placed) is shown by a Rust test.
- **Not yet classified** lists differences the parity audit found that are not
  reviewed yet. Treat them as differences until they move to another section.

## Closed since the audit

The audit of 2026-11-16 (`docs/research/python-sdk-parity.md`) named five items
that put a program ported from Python at risk. Four are closed and no longer
differ:

- Raw-schema tool arguments are validated against the schema before the handler
  runs, in a build with default features, as Python always does. A build with
  `default-features = false` turns validation off.
- A resume from a session store fails at once, removes its temporary directory,
  and starts no CLI when the credentials file cannot be written, as Python
  does.
- Every key the CLI sends inside a structure Python passes through untouched
  (`modelUsage`, the MCP status, the context usage) stays reachable from the
  Rust value and is written back on serialization.
- The unit and end-to-end tests the audit rated weaker than their Python
  originals assert the same facts again.

The fifth, the flat error enum, stays a deliberate difference: the predicates
`Error::is_process()` and `Error::is_cli_connection()` keep the meaning of the
Python `except` clauses, and the enum itself stays flat. It is listed in the
generated tables above.

One more divergence of the audit is closed: the in-process MCP server declares
the capabilities the Python server declares.

## What Rust adds

Items with no Python counterpart, so they appear in no ledger:

- A bridge to the `rmcp` crate (feature `rmcp`) that serves an existing `rmcp`
  server in process, and `SdkMcpTool::typed`, which derives a tool's schema
  from a Rust type. (The `#[tool]` attribute macro is listed in the ledgers: it
  is the adapted counterpart of the Python `tool` decorator.)
- An `Unknown` variant on every enum of the wire, and typed MCP status and
  context usage responses that still keep the keys they do not model.
- `ClaudeAgentOptions::builder()`, which checks the combinations Python checks
  at connect when `build()` is called.
- Termination of the whole process tree of the CLI (a Job Object on Windows, a
  process group on Unix, a parent-death signal on Linux), cleanup when a client
  is dropped, and a lock that serializes `connect` and `disconnect`.
- A scriptable transport (feature `testing`) to test a program without calling
  the API, and the differential harness that produced the wire tables of this
  page.
- The example `session_store_adapter.rs`, a complete session store written from
  scratch.
